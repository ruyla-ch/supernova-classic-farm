# class-mid Mailbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a per-player MySQL mailbox with one welcome mail for each new player, while retaining four plots, carrot-only gameplay, JSON transport, and database locking.

**Architecture:** Keep the single Go server and current synchronous Store/Engine flow. Extend Store with mailbox operations, create `class_mid_mails` during initialization, insert the welcome mail inside registration's existing transaction, and route two mailbox actions through the authenticated WebSocket connection.

**Tech Stack:** Go 1.26, `database/sql`, MySQL 8, `coder/websocket`, Vue 3, TypeScript, JSON.

**Spec:** `docs/superpowers/specs/2026-09-07-mailbox-design.md`

## Global Constraints

- Work only on `class-mid`; do not restore Login/Gate/Coordinator, Shard, Actor, or Protobuf.
- Do not recreate or clear `classicfarm`; only create `class_mid_mails` and isolated test rows.
- Existing users do not receive a backfilled welcome message.
- Mail has title, full body, read state, and creation time; no attachments, delete, expiry, pagination, or push.
- Preserve exactly four plots and carrot-only gameplay.
- Add concise Chinese comments at transaction, ownership, locking, idempotency, and identity boundaries.
- Do not commit or push without the user's explicit instruction.
